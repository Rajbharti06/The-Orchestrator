# API Design Skill

Standards for all APIs generated by Orchestrator X.

## Endpoint Naming

```
GET    /api/v1/users          → list users
POST   /api/v1/users          → create user
GET    /api/v1/users/{id}     → get user
PUT    /api/v1/users/{id}     → replace user
PATCH  /api/v1/users/{id}     → update user
DELETE /api/v1/users/{id}     → delete user
```

## Error Response Format

Always return consistent error objects:
```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Email is required",
    "details": [{ "field": "email", "message": "required" }]
  }
}
```

## Pagination

```json
GET /api/v1/users?page=1&limit=20
{
  "data": [...],
  "pagination": {
    "page": 1,
    "limit": 20,
    "total": 150,
    "pages": 8
  }
}
```

## Required Headers

All API responses must include:
```
Content-Type: application/json
X-Request-ID: uuid
X-Rate-Limit-Remaining: 99
```

## Versioning

- Version in URL path: `/api/v1/`
- Never break existing versions — add v2 instead
- Deprecation header: `Deprecation: true`

## Authentication

```
Authorization: Bearer <jwt_token>
```

- JWT must include: `sub`, `exp`, `iat`
- Token expiry: 24 hours access, 30 days refresh
- Refresh endpoint: `POST /api/v1/auth/refresh`

## Always Include

- `GET /health` — no auth required, returns `{"status": "ok", "uptime": 123}`
- `GET /api/v1/me` — returns current user from JWT
- Rate limiting on all auth endpoints (5/min)
- CORS configured for specific origins (never wildcard in production)
